# 批量整理整个库

## 一、工作流

1. **侦察** → 2. **样稿 1 篇给用户确认** → 3. **备份原文**（`.sy` + `md5sum` 指纹）→ 4. **逐条链路改造**（表格 → 代码块语言 → 标题/序号 → 摘要 → 清理；每条独立分批 + 回读）→ 5. **分类归位**（建父文档、配图标、移文档；删目录单独确认）→ 6. **全量对账**（文档数 / 三件套 / 摘要 / 图标 / 脏块 / 备份逐项对应）

子任务提示词写明：反造假、每步回读验证、备份落盘并 `ls` 证明。

## 二、去重

| 类型 | 识别 | 处置 |
| :--- | :--- | :--- |
| 逐字重复 | 同段落/同代码块文字一致 | 合并到唯一归属，另一处留互见一句 |
| 主题级重叠 | 同主题两篇各写一遍，逐字重合很少 | 不合并；定一个主篇，另一篇留互见 |

**不要合并**：课程渐进式重构案例；流程图相似但演示状态不同；相似度高但方法不同的代码；同一主题的两套独立叙述。
**探针**：收集到 `NodeBlockquote`/`NodeList`/`NodeTable` 就停止递归。

## 三、标点与错字

用 `scripts/punct_scan.py <paths.txt>`（只报告，不落盘）。

**必须保护**：`` `...` `` 行内代码、`((块引用))`、`$...$`、`${...}`、ASCII 省略号 `...`；`(...)` 仅当前面紧跟汉字时转全角（保住 shell 数组 `数组名=(值1 值2)`）；`:` 后不能是 `:` 或 `/`（保住 `std::vector`）；`。` 规则排除后跟汉字（保住 `对象.属性`）。

**筛错字必须加白名单**（GB2312 不可编码会大量误报）：`—`、`·`、`▤`、上标、`™`、`®`、`Á`、`啰嗦` 都合法。改完逐块回读。

## 四、拆分超长文档

### 4.1 口径

每篇超长文档 → 1 篇分类父文档 + N 篇子文档；子文档 1 千 – 1 万字；**每篇首块是摘要引用块（不写 `# 文档标题`）**；父文档与子文档都要有摘要与图标（同目录不重复）。

### 4.2 步骤

1. 全库重扫取当前最大 → 读目标结构（h1/h2/h3 分布、开头孤儿块、0 字空壳章、是否单列表承载全文）
2. 出计划：按节序号取**半开区间** + 硬断言（4.3）
3. 建子文档：官方 `document {action:"create", notebook, path:"<父级 hPath>", title:"<子文档名>"}`（父级必须已存在）；需一次带完整多级路径时用 `scripts/sy_api.py create` → 按原序 `move` 搬「标题 + 内容块」→ 子文档内节标题升 h2
4. **标题层级整体 -1**（原 `##` → `#`、`###` → `##`，不插标题）：`block {action:"update", id, data:"# 章节名", dataType:"markdown"}`；摘要最后 prepend
5. **最后**才 `block {action:"prepend"}` 写摘要 + `attr {action:"set"}` 设图标（早写会被后续搬块的 `parentID=doc` 挤到末尾）
6. 清理父文档（删旧摘要、旧文档标题 h1，保留文档级导语），再补摘要 → 收尾校验（4.5）；批量搬文档用 `scripts/sy_api.py move`（官方 `document.move` 只能单个）

### 4.3 计划期硬断言

- `assert '/' not in doc` —— 子文档名含半角 `/` 会建出嵌套文档
- `assert len(dup) == 0 and tot <= 原文净字符` —— 区间重叠/越界；章节必须章内定位或用**节序号**（全局查找会撞跨章同名节）
- `assert 章内 h3 #1 的前置块 == 仅章标题本身` —— 不成立时人工确认归属（有的章 h2 后藏着导语段落，按节统计显示 0 字会被当空壳删掉）

### 4.4 标题层级判据

| 判据 | 做法 |
| :--- | :--- |
| 章 h2 别落空 | 区间起点是 h3 #1 时，用 `head = 章块[:h3[0]]` 并入首段 |
| 尾段孤儿 h3 升 h2 | 尾段 = 某章后半节（h3）+ 后续章（h2）拼成时 → 把开头的 h3 升 h2 |
| 零标题文档 | 按块序号在语义缝隙切分，不新增小节标题，靠摘要写范围（无标题也合规，**不补 `# 文档标题`**） |

### 4.5 不可拆与收尾校验

**不可拆**：① 全文是单个 NodeList；② 正文是超大列表项。移动列表项会报 `invalid block structure: NodeDocument can...` / `move block failed` → 记为「结构原子」跳过。**节整体是列表可以搬**。

**收尾校验**：

1. 代码块**全集双侧比对**（缺失 + 新增都看；glob 排除既有子文档，否则把老文档的代码块算成「新增」）
2. `scripts/sy_audit.py <数据目录> --paths-file <paths.txt>`：逐篇指标 + 合计（表格三件套 / 图标 / 首块摘要 / 代码块语言 / H4+ / 空段 / 分隔线 / AI 痕迹）
3. `scripts/sy_compliance.py <数据目录>`：**全规则终检**（首块摘要引导词、无同名空壳标题、不跳级、每篇有图标、同目录图标不重复、表格三件套、代码块语言、空段落/分隔线/AI 痕迹）→ 期望「8 类规则 0 违规」
4. `scripts/punct_scan.py <paths.txt> [--ignore <清单>]`：待改块数 0（白名单写进 `punct-ignore.txt`）
5. 父文档多出的空段落清掉

### 4.6 拆分专属坑

| 迁移 | 坑 | 要求 |
| :--- | :--- | :--- |
| 官方 `document.create` | `path` 是**已存在父级**、名字放 `title` | 写完整多级 path 报 `parent path not found`；要建多级用 `scripts/sy_api.py create` |
| 搬块 | `move` 必须给 `parentID` + `previousID` | 缺 `parentID` 报错；只给 `parentID` 静默无效；两个 MCP 都不会自动带走内容块 |
| 拆分 | **h1 会藏在子树里**（仅旧口径；现已改为不写文档标题 h1） | 内核把 h1 挂进第一个 h2 的子树随章搬走 → 表现为审计 `H1` 列 > 1；删多余 h1 只减 1 块（子块上提） |
| 摘要 | 批量删引用块会误删正文引用块 | 只删「文档首块且是 `NodeBlockquote`」那一个，或按块 ID 精确删 |
| 脚本 | 文档 id 校验 pattern `^\d{14}-[a-z0-9]{7}$` | id 一律从工具返回值取（脚本间用 `store`/`load` 传递），不手抄 |
| 统计 | 字数虚高 | 不要「递归收集 BODY 节点文本」；`NodeText` 与 `TextMarkTextContent` 需同时收（互补） |
| 快照 | `repo {action:"create"}` 可能返回 `no changes` | 回滚靠 `backup/*.sy` + 思源「数据历史」 |

## 五、数据完整性核对

1. **备份覆盖**：逐篇 `cp` 原文 `.sy` + 指纹，核对无遗漏
2. **逐篇净字符比对**：`NodeText + TextMarkTextContent + NodeCodeBlockCode` 去空白字符数，备份 vs 现状；只关注净减少篇目并逐篇解释
3. **全库搜索复核**：疑似消失的文本拿到现状全库 `.sy` 搜（去 `\u200b`、归一化标点）

**不要按文本节点逐条比对**（全假阳性）。
**拆分类额外证据**：每篇代码块全集双侧比对 + 计划断言；全库代码块/表格总数应与拆分前**逐一相等**（增量只能来自用户新增文档）。

## 六、校验脚本与 SQL

| 脚本 | 用途 |
| :--- | :--- |
| `scripts/sy_compliance.py <数据目录>` | **全规则终检**（8 类规则），一次性把「规范是否落地」查完 |
| `scripts/sy_patrol.sh <数据目录> [报告目录]` | **定期巡检**：合规 + 标点两项，报告落 `patrol-<时间>.txt`，无待改退出码 0 / 有待改 1（可接 cron） |
| `scripts/sy_audit.py <数据目录> --paths-file <paths.txt>` | 读 `.sy` 出逐篇指标 + 合计（三件套 / 图标 / 首块摘要 / 代码块语言 / H4+ 计数 / 空段 / 分隔线 / AI 痕迹） |
| `scripts/flatten_headings.py --plan <plan.json>` | 旧库标题口径转换（删 `# 文档标题` + 全标题层级 -1，见九） |
| `scripts/unify_summary_lead.py` | 旧库摘要引导词统一为 `**摘要**`（见九） |
| `scripts/punct_scan.py <paths.txt> [--db …] [--with-adj] [--plan-out plan.json]` | 标点规范化扫描，只报告不落盘 |
| `scripts/sy_api.py sql "<SELECT>" --out f.json` | 取全量清单（自动分页，内核单次只回 32 行） |
| `scripts/sy_api.py docs <boxID> --out f.json` | 列文档 id + hpath |

两者只读；路径用「先看原路径存不存在，不存在再拼数据目录」，**不要用 `os.path.isabs` 判 DB 的 `path` 列**（形如 `/a/b/c.sy`，看着像绝对路径其实相对笔记本根目录）。

```sql
SELECT count(*) FROM blocks WHERE type='d' AND box='<boxID>' AND hpath LIKE '/容器云/%';   -- 数量用 COUNT
SELECT count(*) FROM blocks WHERE box='<boxID>'
  AND ((type='p' AND content='' ) OR type='tb' OR content LIKE '%🧑‍💻%');                -- 脏块（分隔线是 type='tb'）
SELECT * FROM refs WHERE def_block_id='<docID>';                                          -- 真双链
```

摘要覆盖率、列宽合格性、`TableAligns` SQL 查不出来，只能扫 `.sy`（判据见 `SKILL.md` 三）。

## 七、分类与索引约定

- **一层一个维度**：目录（文档树）承担主题域；数据库字段承担目录表达不了的属性。不要把「主题」同时写进目录和字段
- **字段**：`用途`（学习/面试/操作/工作）、`状态`（未整理/已整理）、`更新时间`、`主键`（block 绑定文档）；选项名字数统一，一个字段一个维度，用「状态=未整理」代替单独的「杂记」类别
- **数据库不是容器**：行是块引用，文档仍须有物理位置；绑定已有文档用官方 `database {action:"item_add", blockID}`；建 select 字段没有「设置选项」接口，但写不存在的选项名会自动创建（用探针行灌完再删）；视图（分组/排序/筛选）MCP 不支持，改 `storage/av/<avID>.json` 只在重启后生效
- **合并库前先分辨**：字段是「主键/用途/状态/时间」的是索引库（可合并）；「联系人/IP/服务」的是业务数据（合并会污染）

## 八、口径红线

### 8.1 空壳标题（标题下无内容、紧跟同级或更高级标题）

| 类型 | 特征 | 处理 |
| :--- | :--- | :--- |
| **分组型** | 下位小节在命名与语义上都从属它（`## string容器` → `## string 基本概念`…共 9 节） | 子节降一级（分组保持） |
| **漏写型** | 作者只是忘写内容，后续同级节与它并列（`### 文件描述符` → `### PCB 进程控制块`） | 不动 |

- **不删**（丢分组语义）、**不升**（会把后面所有同级标题收编，边界没有依据）
- **嵌套分组**（空壳紧邻空壳，如 `String：扩展操作` → `数据表主键不重复` → `数据表主键不重复：业务场景`）：外层保持，内层降一级，内层下面的节再降一级；这层人工看结构定
- **可自动识别的情形（严格命名关系）**：分组名去掉「容器/操作/类型/设置/机制/算法…」后缀得关键词（≥3 字），紧随的同级区段（到下一个同级空壳）≥80% 标题以该关键词开头且区段 ≥2 项
- 位置规则与主题词法都不可靠 → **不要全库自动降级**
- 不要用「空壳标题数」当质量指标

### 8.2 其他不要动

| 不要动 | 后果 |
| :--- | :--- |
| 合并单元格表、单元格含裸 `\|` 的表 | markdown 表达不了，重写丢结构 |
| 文件末尾的列表项占位空段落 | 删后内核立即用新 id 补回 |
| 行内代码内的标点、`std::` / `=(a b c)` / `对象.属性` | 改坏风险高于收益 |
| `™` / `®`、`—` / `·`、上标 | 不是错字 |

## 九、旧库整体升级（一次性）

### 9.1 标题：删 `# 文档标题` + 全部标题层级 -1

旧文档若是「`# 文档标题` + `##` 章节」形态 → 用 `scripts/flatten_headings.py`：

1. 扫 plan：每篇恰好 1 个 h1 且文本 == 文档标题、h1 前只有摘要 → `{"doc":…, "h1":…, "titles":[[id, 原层级], …]}`
2. 存改前快照（每篇块数 + 全部标题 id/层级/文本），再跑 `python3 scripts/flatten_headings.py --plan <plan.json> --workers 10`
3. 脚本：删 h1 → 其余标题用 `getBlockKramdown` 取原样、**只改 `#` 前缀**写回（文本零重解析）
4. 校验：块数 -1、标题层级 -1、标题文本逐字一致、首块仍是摘要、原 h1 id 已不存在

坑：取 kramdown 的正则**不要用 `re.S`**（空标题的 kramdown 是 `###` + 下行 IAL，`re.S` 会把 IAL 吞进标题文本，恢复用 dom 清空文本）；比对两侧要用**同一个提取函数**（一侧反转义一侧不反转义会出一堆假阳性；`&amp;`/`&lt;` 是 `.sy` 的规范转义，不是文本变化）。

### 9.2 摘要：引导词统一为 `**摘要**`

`scripts/unify_summary_lead.py`（全库首块摘要的 strong 标记文本 `要点`/`结论`/`背景` → `摘要`）：

1. `--dry-run` 看分布 → 跑一遍（内核 API 并发 10，1200 篇约 20 秒）
2. 手法：`getBlockDOM` → 用正则**只替换第一个 `<span data-type="strong">旧词</span>` 的文本** → `updateBlock`（`dataType:"dom"`，摘要正文零重解析）
3. 校验：改后全库引导词分布只剩「摘要」；抽查正文里的普通词（如「处理结论」「fork 的要点」）不受影响

### 9.3 命名统一（中英文空格 + 缩写大小写）

一次性扫出来改掉，成本低收益高（实测 99 篇）：

1. 扫：找出文档名里 **CJK 与 ASCII 相邻无反引号** 的（`Code-Server部署`、`ArchLinux配置IP`）与 **英文缩写非官方大小写** 的（`Http基础`、`SQL语句`、`Mybatis`）
2. 规则：CJK 两侧补空格；缩写按官方大小写（HTTP / SQL / JSON / XML / HTML / API / JVM / DNS / TCP / UDP / IOC / AOP / JSP / JDBC / JPA / DAO / JWT / HTTPS / MyBatis / GQL…）；数字不算英文（`HTTP2.0` 不加空格）
3. 执行：`document {action:"rename", id, title}`（改名不动块 id，因此 `((块引用))` 不断链；实测零受影响）
4. 校验：改名后同目录零重名；再扫一遍「CJK 与 ASCII 相邻」应为 0

### 9.4 拍平纯转接层

**判据**：中间目录只有 1 个子文档（`示例工程 > 已验证示例`、`示例 > TLS 证书 > README`、`Prometheus 中文文档 > 简介 > Prometheus 简介`）。
**不要拍**：主题目录即使暂只 1 篇也保留（`/技术/工具/Git > Git 总结（博客版）` 就是主题，等它生长）。

1. 先移子文档到目标父目录：`filetree/moveDocsByID`（或 `scripts/sy_api.py move`）—— **父子同名时先改名再删，否则两个 `README` 会同名共存**
2. 确认原目录 `hpath` 前缀下的文档数为 0（`SELECT count(*) … WHERE hpath LIKE '<目录>/%'`）
3. **先删子、后删父**：父文档带子树一起删
4. 删除用 `document {action:"delete", id}`；**用 `block {action:"delete"}` 会静默无效**
5. 拍完立即跑 `sy_compliance.py`：子文档上移到新父目录后常与兄弟撞图标（实测连撞 5 次）
